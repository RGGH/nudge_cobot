How to code a myCobot robot arm in Rust

We’ll build one small program from scratch: it connects to the arm, reads where it is, nudges the shoulder toward the sky, and checks that it really got there. Every step adds a few lines, and at the end you’ll have the whole file.

What you need

  • Rust installed (rustup gives you cargo).
  • A myCobot whose Raspberry Pi runs a TCP server on port 9000 (ours lives at 192.168.1.236:9000). The server is a go-between: we talk to it over the network, and it talks to the arm over the serial port.
  • Clear space around the arm.
Safety first. Robot arms don’t know what’s in their way. Keep hands, cables and mugs clear, and start with small, slow moves.

Step 1

Set up the project

We use only Rust’s standard library, so there’s nothing to download.

cargo new cobot
cd cobot

Open src/main.rs and delete what’s there. We’ll fill it in one piece at a time.

Step 2

Teach the code the robot’s vocabulary

Start the file with our imports and a handful of named values. Naming things now (instead of sprinkling 0x20 everywhere) means future-you can actually read the code.



A few ideas here:


    

  • Commands are single bytes. 0x10 means “power on”, 0x20 means “tell me your joint angles”, 0x22 means “go to these angles”. We tuck them into a cmd module so they read like cmd::POWER_ON.
    • 

  • Angles is just six f32s, one per joint, in degrees.
    • 

  • Joint limits are the min and max each joint can safely reach. These are the myCobot 280 numbers; change them for other models.
    • 







Step 3

Wrap messages in envelopes


The robot only understands messages in a fixed shape, a bit like an envelope with a start stamp and an end stamp:




FE FElencmddata…FA


start markerdata length + 2what to dothe detailsend marker






frame(0x20, &[]) gives [254, 254, 2, 32, 250], which is the “where are you?” message. The u8::try_from line makes the program stop loudly if a payload is too long to fit, instead of quietly wrapping around to a wrong number.






Step 4

Decode replies and add safety checks


Three small, pure functions: they take data in and give data out, with no robot involved. That makes them easy to trust and easy to test.




    

  • parse_angles looks for a complete 17-byte reply anywhere in what came back. Each angle is a 16-bit number in hundredths of a degree, so 9000 means 90.00°. It searches because a stray late reply may sit in front of the one we want.
    • 

  • check_limits refuses any target outside the joint limits. The !(lo..=hi).contains(a) trick also rejects NaN.
    • 

  • step_toward_zero moves up to step degrees toward 0 (arm vertical) and stops at 0. A naive “subtract 5” would overshoot if you’re already 2° away.
    • 







Step 5

Open the connection


Now the part that touches the network. A Cobot wraps a TcpStream. Below we open the impl block; we’ll add more methods to it in the next step, so leave it unclosed for now.




    

  • The handshake: the server wants three messages first (serial port, baud rate, timeout) and answers 1 to each if it’s happy.
    • 

  • One message out, one reply in: send_recv is our basic “say something, hear back” move.
    • 

  • Odd detail: this server wants the frame as the text of a list, like "[254, 254, 2, 32, 250]". Rust’s {:?} on a Vec<u8> prints exactly that.
    • 

  • drain empties any late replies waiting in the socket, so we never mistake an old answer for a fresh one.
    • 







Step 6

Read, move, and wait


Three more methods go inside the same impl Cobot block, and then we close it.




    

  • get_angles retries up to five times, because the server only waits 50 ms for the robot and the answer sometimes arrives one request late.
    • 

  • send_angles checks the limits first, then packs each angle as hundredths of a degree into two bytes, followed by the speed (0–100).
    • 

  • wait_until_reached is the honest part. The reply to a move command means nothing, so we keep reading the real angles until every joint is within the tolerance, or give up after a timeout. Better than hoping a fixed sleep was long enough.
    • 







Step 7

Put it together in main




Read it like a recipe: connect, note where we start, power on, pick a target 5° closer to vertical, move slowly (speed 20), wait until we arrive, and print where we ended up. The address comes from the command line if you give one.


Try it with the arm clear: cargo run -- 192.168.1.236:9000
